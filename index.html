01 — Problem Statement

Detecting Toxicity at Scale

Online platforms receive millions of comments daily. Manual moderation doesn't scale — automated content classification is essential for maintaining healthy communities. This Kaggle competition challenged participants to build a multi-class classifier that assigns each comment to one of four toxicity levels.

The core difficulty: the dataset is severely imbalanced. Hate Speech makes up only 2.8% of comments — a model that ignores it entirely would still appear to perform well under naive accuracy metrics. The competition metric was Macro F1, which treats every class equally regardless of size, forcing models to genuinely learn all four categories.

02 — Dataset

Rich Metadata + Raw Text

The dataset contained 198,000 training and 102,000 test comments, each with 15 columns covering the raw comment text plus structured metadata signals.

# Dataset columns columns = [ 'created_date', # timestamp of comment 'post_id', # thread identifier 'emoticon_1/2/3', # emoticon usage flags (0/1) 'upvote', # community upvotes received 'downvote', # community downvotes received 'if_1', 'if_2', # interaction flags 'race', # target identity: race mentioned 'religion', # target identity: religion mentioned 'gender', # target identity: gender mentioned 'disability', # target identity: disability mentioned 'comment', # raw text — primary feature 'label' # target: 0/1/2/3 ]
The identity columns (race, religion, gender, disability) are particularly valuable for Hate Speech detection — comments targeting specific demographic groups are strong indicators of class 3. These were label-encoded and stacked with TF-IDF features using scipy.sparse.hstack.
03 — End-to-End Pipeline

From Raw Text to Submission

01
Exploratory Data Analysis
Class distribution analysis, comment length distribution, upvote/downvote patterns per class, identity column frequency. Confirmed severe class imbalance (Neutral:Hate = 20.6:1) and established that text alone is the primary signal.
02
Text Preprocessing
Lowercasing, regex-based cleaning (URLs, special characters), whitespace normalisation. Avoided stopword removal — for toxicity detection, words like "you" and "they" in context are meaningful.
03
Feature Engineering
TF-IDF vectorisation (100K features, unigrams + bigrams, sublinear_tf=True) on comment text. Metadata features (emoticons, upvote/downvote ratio, identity flags) label-encoded and sparse-stacked using scipy.sparse.hstack to preserve memory efficiency.
04
Stratified Train/Validation Split
85/15 split with stratify=y to maintain class distribution in both sets. Validation set: 29,700 samples. Used StratifiedKFold(n_splits=5) for cross-validation during model tuning.
05
Model Training with Class Balancing
Logistic Regression and LinearSVC, both with class_weight='balanced'. Balanced weights computed as n_samples / (n_classes × count_i), giving Hate Speech a ~8.9× loss multiplier vs Neutral's 0.43×.
06
Weighted Probability Ensemble
LR provides predict_proba directly. LinearSVC decision_function scores converted to probabilities via softmax (scipy.special.softmax). Final blend: 40% LR + 60% LinearSVC — grid-searched across weight combinations.
07
Per-Class Scale Tuning (Nelder-Mead)
scipy.optimize.minimize with Nelder-Mead method used to find optimal per-class probability scaling factors that maximise validation Macro F1. Boosted F1 from 0.8237 → 0.8293 on validation. Applied to test set for final submission.
04 — Feature Representation

TF-IDF — Why It Was the Right Choice

Text representation is the most consequential decision in any NLP pipeline. The choice between raw counts, TF-IDF, and dense embeddings determines what signal the model can see.

# TF-IDF configuration tfidf = TfidfVectorizer( max_features=100_000, # top 100K tokens by corpus frequency ngram_range=(1, 2), # unigrams + bigrams ("go back", "hate speech") sublinear_tf=True, # 1+log(tf) instead of raw count analyzer='word' # word-level tokenisation ) # Combine TF-IDF + metadata features X_train = hstack([tfidf_train, meta_train]) # scipy sparse hstack

Why TF-IDF over alternatives: Toxicity detection is fundamentally keyword-driven. Specific slurs, phrases, and word combinations are the signal — not nuanced semantic context. TF-IDF captures this perfectly while staying memory-efficient in sparse format (~tens of MB vs ~150 GB if dense). BERT would likely score 1-3% higher but requires GPU and hours of fine-tuning — overkill for a competition where classical NLP already reaches 0.82+ macro F1.

Why bigrams matter: "go" and "back" are individually harmless. "go back" is a recognised xenophobic phrase. Bigrams expose these compound signals that unigrams miss entirely.

Why sublinear_tf: A comment repeating a slur 100 times shouldn't get 100× the feature weight of one saying it once. log(1+100)=5.6 compresses the outlier while preserving the ordering. More robust to spam-style repetition.

05 — Models

Linear Models on Sparse Text

used · 40% ensemble weight
Logistic Regression
One-vs-Rest multiclass via 4 binary classifiers. Each word in the 100K vocabulary gets a learned weight per class. class_weight='balanced' scales the cross-entropy loss by inverse class frequency. Outputs calibrated probabilities via sigmoid — directly usable in the ensemble blend without any conversion. Val Macro F1: 0.8218. Public: 0.82010.
used · 60% ensemble weight
LinearSVC
Support Vector Machine with linear kernel. Finds the maximum-margin hyperplane in 100K-dimensional TF-IDF space. No predict_proba — outputs raw decision_function scores which were converted to probabilities via softmax before blending. Marginally lower val F1 than LR (0.8186 vs 0.8218) but better Kaggle public score (0.82345 vs 0.82010), hence 60% weight. C=1.0 (default).
tried, not final
XGBoost (Meta-learner)
Attempted as a stacking meta-learner on top of LR and SVC OOF (out-of-fold) predictions. Did not outperform the simple weighted blend — gradient boosting on only 4 probability inputs (per class) lacks sufficient feature signal. Excluded from final submission.
considered, not used
BERT / Transformers
Would likely push Macro F1 to 0.85+. Not used due to GPU unavailability on free Kaggle tier and the significant fine-tuning overhead. The TF-IDF + linear approach was already competitive and far faster to iterate on.

Class Imbalance Strategy

With a 20.6:1 Neutral-to-Hate ratio, without intervention the model's loss function is dominated by Neutral samples. Three strategies were evaluated:

# Step 1: LR probabilities — already calibrated proba_lr = best_lr.predict_proba(X_val) # Step 2: SVC scores → probabilities via softmax scores_svc = svc.decision_function(X_val) proba_svc = softmax(scores_svc, axis=1) # Step 3: Weighted blend (grid-searched) proba_blend = 0.4 * proba_lr + 0.6 * proba_svc # → Val Macro F1: 0.8237 # Step 4: Per-class scale tuning via Nelder-Mead # best_scales = [1.1678, 0.9802, 1.0611, 0.8750] proba_scaled = proba_blend * best_scales pred = np.argmax(proba_scaled, axis=1) # → Val Macro F1: 0.8293 (+0.0056 improvement)
The per-class scales [1.17, 0.98, 1.06, 0.87] tell a precise story: the model was systematically underconfident about Neutral (×1.17 boost), slightly overconfident about Mild Toxic (×0.98 shrink), slightly underconfident about Offensive (×1.06), and overconfident about Hate Speech (×0.87 shrink — many of those confident hate predictions were false alarms). Scale tuning corrects these systematic biases at zero training cost.

08 — Key Learnings

What Actually Moved the Score

+
Metric choice forces honest evaluation
Accuracy was 91% — Macro F1 was 0.82. The 9-point gap exposed exactly how much the model was leaning on the Neutral majority. Building everything around Macro F1 forced genuine improvements on minority classes.
+
Softmax conversion was essential for ensemble
LinearSVC's decision_function outputs raw margin scores, not probabilities. Blending these directly with LR's probabilities would be scale-incompatible. softmax(scores, axis=1) normalises them to the same [0,1] probability space, making the blend mathematically meaningful.
+
Nelder-Mead scale tuning: +0.006 F1 for free
Post-processing probability scaling with scipy.optimize requires no retraining. It corrects systematic per-class biases that neither class_weight nor the models themselves can fix. A simple but high-leverage technique.
−
Hate Speech F1 capped at 0.67 — the hard limit
With only 5,544 hate speech samples in a 100K-dimensional space, the model is inherently uncertain about the nuanced boundary between offensive and hate. The next frontier is BERT fine-tuning, which would understand context, sarcasm, and implicit targeting that TF-IDF misses.
